## Wiring
- **`RecordingPipeline`** (`mobile/lib/app/recording_pipeline.dart`), one per recording, created by the shell
  at record start: `live` (`ValueListenable<LiveTranscript>`), `start()`, `stop(profile)`, `dispose()`.
  - `MicrophonePipeline`: streaming providers (`service.streamsLive`: Bailian realtime, **Soniox too**) →
    `startLiveSession()` + PCM stream → `finishLiveSession`; batch (Qwen-ASR) → WAV + `beginBatchListening()` →
    `transcribe`. Soniox used to upload a WAV after stop; it now streams PCM live (T1's session).
  - `DebugCapturePipeline`: adapts the existing `DebugCapture` test hook (batch-like).
  - `LiveFixturePipeline` (DEBUG, item 5), below.
- **Shell** (`app/mobile_shell.dart`): mirrors the pipeline's `live` into one `ValueNotifier` given to
  `RecordView.transcript` (T2's fake type deleted; imports point at `services/live_transcript.dart`). Stop while
  the provider is still connecting waits for the start. Record during processing is ignored (it used to call
  stop again).
- **Failure (L2/L3)**: a drop / provider error while listening stops the recording at once; one after Stop
  fails the stop. Either way `live.value.text` (committed + pending, trimmed) becomes this recording's draft
  (`_recordDraft`), the area shows it editable, status "Recording stopped" + "What was heard is kept here and in
  Drafts. (<error>)" with the fix button **Record again** (`StatusFix.retry`). Nothing heard → no draft,
  "Recording failed" + Record again.
- **Auto-publish kept** (decision c) but without the snack bar: it covered Copy/Done for 4 s; the status line
  already says "Copied. Paste it anywhere, or insert it from the keyboard."
