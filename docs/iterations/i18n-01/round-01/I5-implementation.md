# I5 — translations (9 languages) + glossary: implementation notes

Branch `i18n-01-i5-translations`, base `main` @ be545f7. Model: Opus. Tested source state: the PR head (see
STATE.md; renders and builds were run on the commits listed there).

## What changed
- **Glossary** `docs/i18n/glossary.md`: product terms, built-in profile names, Apple names per language
  (Settings paths, Allow Full Access, Shortcuts / App Shortcuts, Automation trigger names, Home Screen), return
  key titles, the five Siri/Shortcuts phrases, per-language notes. Key choices: zh "profile" = **模式** (not
  配置文件/描述檔 = Apple config profiles, not 預設 = "default" in Taiwan; the Bailian recognition switch became
  识别方式/辨識方式 so it does not collide); the Desktop tab = 电脑/電腦, Computer (de, it), Ordenador (es),
  Ordinateur (fr), Computador (pt-BR); fr Record tab/key = "Dicter" ("Enregistrer" is already Save).
- **ARB** `mobile/lib/l10n/app_{ja,zh_Hant,ko,de,es,zh_Hans,fr,pt_BR,it}.arb`, every key; plus the gen-l10n
  fallbacks `app_zh.arb` (= zh-Hans) and `app_pt.arb` (= pt-BR) — gen-l10n needs a plain-language file for
  scripted/regional ones. Plurals: CJK use `other` only; European languages keep `=1`/`other`. The
  translation-profile prompts (`profile*ToEnIntent`, `profileZhToEnIntent`, `profileTranslateToEnIntent`) stay in
  English, as their ARB descriptions ask; the other built-in prompts and names are translated (I3 creates them
  from the device language). `l10n.dart` comment updated ("falls back" no longer holds).
- **Native** (`tool/i18n/native.json` → `tool/i18n_native.py`): all keys of `ShinsokuKeyboard/Localizable.xcstrings`,
  `Runner/Localizable.xcstrings`, `Runner/InfoPlist.xcstrings` (state `translated`; the `%@` entity entry stays
  `shouldTranslate: false`), and `Runner/<lang>.lproj/AppShortcuts.strings` for 9 languages, registered in the
  `AppShortcuts.strings` variant group with the `xcodeproj` gem (pbxproj diff: 18 added lines, nothing removed).
  The native files are generated: edit `native.json`, run `python3 tool/i18n_native.py`; R07 fails if they drift.
- **Use-in-apps quotes**: `useInAppsReadyMade` quotes the translated "Switch ${applicationName} to ${profile}"
  phrase with the translated Chat name (e.g. ja 「Shinsokuをチャットに切り替える」, zh-Hans “将Shinsoku切换为聊天”,
  de „Shinsoku auf Chat umstellen“); `useInAppsOpenStep3`/`CloseStep2` name the translated *Set Shinsoku
  Profile* action. R07 checks both.
- **Checks**: `tool/check_xcstrings.py` (R06) now also requires a translated value in all 10 languages with the
  English placeholders (`%@`, `%lld`, `%d`, `${…}`), and every `<lang>.lproj/AppShortcuts.strings` with every
  phrase, the same `${…}` and a pbxproj reference. New `tool/check_arb.py` (R07): same keys, placeholders,
  plural variable and CLDR/`=N` forms with `other`, fallback copies equal, the quoted Shortcuts names above;
  R07 also runs `i18n_native.py --check`. Negative tests: a dropped ja `%@`, a missing it value, a ja phrase
  without `${profile}`, a German plural with an invented form, a renamed placeholder, a Chat name that no longer
  matches the quote — each fails. Rule **M12** in `docs/review_rules.md`.
- **Scene tests** (`KeyboardSceneTests/`): `SceneTestCase.keyboardZhHans` (generated from native.json) and
  `variants(_:)` — `key()`, `statusText()`, the profile button (`模式`), its value (`<name>，只读`), the Record key in
  `ensureSystemKeyboard` and the intent dialog (`Shinsoku 模式：<name>`) accept English or zh-Hans. Shortcuts tile
  titles and runner statuses/Record tab got zh-Hans entries. **Behaviour change:** the runner is now launched with
  `-AppleLanguages (en)` (in `setUp` and `launchRunner`), like Safari/Settings/Shortcuts already were, so the app
  UI and the built-in profile names created on a first launch stay English; a runner the keyboard opens via
  `shinsoku://dictation` still follows the system language (hence the zh-Hans statuses).
- **Review package** `docs/i18n/review-zh.md` (generated by `tool/i18n_review_zh.py`): 291 strings, English →
  zh-Hans → zh-Hant, grouped by screen (app screens, keyboard, Shortcuts actions, Siri phrases, permission prompts).

## Host renders (tier A) — `build/ui-review/i18n-01/round-01/i5-<locale>/`
- All 10 locales + pseudo: 192/192 images each, no overflow or layout exception. Full review sample per the
  user's decision: en (`i5/`), ja, de; zh-Hans, zh-Hant, ko, es, fr, pt-BR, it rendered for the automated check.
- **Render fix:** host renders loaded only SF Pro, so CJK text was boxes. `host_review_test.dart` now loads the
  system CJK font for ja (Hiragino Sans W3), zh (PingFang from the font assets; Hiragino Sans GB fallback) and ko
  (Apple SD Gothic Neo) in place of SF (the test engine has no per-glyph fallback); Latin text in those renders
  is the CJK font's Latin, slightly wider than SF. The `.json` records the font.
- **Clipped text:** for locales other than en, paragraphs cut by their line limit are now listed (`CLIPPED` in
  `run.log`, `clippedText` in the `.json`); only pseudo fails on them. In every locale the only cut paragraphs
  are the two long English sample transcripts in the draft list (by design, two-line rows).
- **Strings shortened:** none. Two component fixes instead (`mobile/lib/ui/`, coordinator please review):
  1. `SkSegmented` (equal-width): a single-word label that does not fit shrinks (FittedBox, scale-down) instead
     of breaking mid-word — German "Einstellungen" broke as "Einstellunge/n" in the Duo landscape pane switcher.
     Multi-word labels still wrap to two lines. English renders unchanged.
  2. `SkIconButton`: the Tooltip now sits inside `SkPressable` instead of around it. German Settings at 200 %
     text failed with "Invisible SemanticsNodes should not be added to the tree" (the key field's eye button, cut
     by the viewport edge, became an empty-rect child of the tooltip's overlay portal). Same visuals and labels;
     `flutter test` unchanged.
- Known cosmetic (not fixed): Japanese line breaks follow Flutter's default (a line can start with ン」 in Use in
  apps); same engine on device.
